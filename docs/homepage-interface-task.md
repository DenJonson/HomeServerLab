# Задача: интерфейс главной страницы

## Контекст

Текущий стек - это командный центр домашней лаборатории на Raspberry Pi. Он дает
единую HTTP-точку входа через Caddy, доступную только через Tailscale или
локальное имя, навигацию через Homepage и наблюдаемость через Prometheus,
Grafana, node_exporter, cAdvisor, Glances и textfile-метрики.

Главная страница не должна становиться NAS-панелью, файловым менеджером или
универсальной админкой. Ее роль - быть первым экраном локальной сети: показать,
что с системой все в порядке, объяснить, какие сервисы доступны, и быстро
провести к сервисам, которые развернуты отдельными compose-проектами.

Планируемые прикладные сервисы:

- база знаний, развернутая отдельным сервисом;
- панель управления умным домом, развернутая отдельным сервисом.

Homepage должен давать ссылки на эти сервисы и базовую проверку доступности, но
не должен встраивать их управление или владеть их данными.

## Цель

Спроектировать и реализовать полезную, функциональную конфигурацию Homepage для
главной страницы homelab.

Страница должна за один взгляд отвечать на три вопроса:

1. В порядке ли Raspberry Pi и мониторинговый стек?
2. Какие пользовательские сервисы доступны прямо сейчас?
3. Куда перейти для диагностики или обслуживания?

## Не входит в задачу

- NAS-панель.
- Ярлык файлового браузера, пока отдельный файловый сервис не будет явно
  добавлен позже.
- Управление умным домом внутри Homepage.
- Редактирование базы знаний внутри Homepage.
- Публикация в публичный интернет; доступ остается локальным или через
  Tailscale.
- Замена Grafana: Homepage должен кратко показывать состояние и вести к
  дашбордам, а не дублировать их.

## Структура интерфейса

### Система

Назначение: первый раздел страницы, сфокусированный на здоровье хоста и
базовой уверенности, что все живо.

Содержимое:

- CPU, память, температура, uptime и использование root-диска Raspberry Pi через
  существующий виджет Glances.
- Индикаторы состояния Homepage, Caddy, Grafana, Prometheus, node_exporter,
  cAdvisor и Glances.
- Ссылка на дашборд Grafana `Homelab Overview`.
- Прямая ссылка на панель Grafana `Compose Projects`.

Ожидаемое поведение:

- Обычный пользователь видит состояние хоста без открытия Grafana.
- Администратор переходит в Grafana только когда нужна детализация.

### Сервисы

Назначение: основной каталог неинфраструктурных сервисов.

Начальные карточки:

- База знаний
  - Адрес: `http://wiki.pi.home.arpa` или финальное выбранное имя.
  - Описание: локальная документация, заметки, инструкции и домашние знания.
  - Ответственность Homepage: только ссылка и проверка доступности.

- Умный дом
  - Адрес: `http://homeassistant.pi.home.arpa` или финальное выбранное имя.
  - Описание: освещение, датчики, автоматизации и управление устройствами.
  - Ответственность Homepage: только ссылка и проверка доступности.

Ожидаемое поведение:

- Эти карточки визуально важнее внутренних мониторинговых инструментов.
- Описание каждого сервиса написано пользовательским языком, а не языком
  реализации.
- Если сервис недоступен, Homepage показывает статус, но не пытается его
  чинить.

### Обслуживание

Назначение: инструменты для диагностики и сопровождения.

Содержимое:

- Grafana: дашборды по хосту, контейнерам и состоянию compose-проектов.
- Prometheus: сырые метрики и PromQL, доступные только через Caddy.
- Portainer: опциональная Docker-админка, показываемая только если намеренно
  включен compose profile `admin`.
- Caddy: скорее справочная карточка о единой точке входа, а не отдельный
  пользовательский пункт назначения.

Ожидаемое поведение:

- Инструменты обслуживания доступны, но не конкурируют с пользовательскими
  сервисами.
- Опциональные админские ссылки явно помечены как опциональные.

### Документация

Назначение: быстрые справочные ссылки для сопровождения стека.

Содержимое:

- документация Homepage;
- документация Caddy;
- документация Docker Compose;
- документация Prometheus;
- документация Grafana;
- админ-консоль Tailscale.

Ожидаемое поведение:

- Внешняя документация отделена от локальных сервисов.
- Ссылки на внешние сайты открываются в новой вкладке.

## Изменения относительно текущего каркаса

В `homepage/services.yaml`:

- Переименовать группы в пользовательские русские названия: `Система`,
  `Сервисы`, `Обслуживание`.
- Удалить текущий пример `Files` из `Service Catalog`; NAS-панели вне области
  задачи.
- Переименовать `Wiki` в `База знаний`.
- Переименовать `Smart Home` в `Умный дом`.
- Оставить в описаниях явное указание, что база знаний и умный дом являются
  внешними сервисами, а Homepage только предоставляет доступ.

В `homepage/settings.yaml`:

- Оставить русскую локаль.
- Оставить компактные ряды: это рабочая стартовая страница, а не лендинг.
- Предпочтительный порядок разделов: `Система`, `Сервисы`, `Обслуживание`,
  `Документация`.

В `caddy/Caddyfile`:

- Добавлять маршруты для базы знаний и умного дома только после подключения их
  контейнеров к сети `homelab_frontend`.
- Сохранить понятные комментарии-шаблоны для будущих внешних сервисов.

## Критерии готовности

- Первый экран показывает здоровье хоста и два планируемых пользовательских
  сервиса.
- На странице нет NAS или файловой панели.
- Мониторинг и админские инструменты доступны, но визуально вторичны.
- У каждой локальной карточки есть адрес, описание, иконка и проверка
  доступности, если она практически возможна.
- Внешние сервисы остаются отдельными compose-проектами, подключенными через
  `homelab_frontend`.
- README остается правдивым: командный центр дает точку входа, навигацию и
  наблюдаемость, но не размещает прикладные сервисы внутри себя.
